Capabilities

Everything you need.

AES-256-GCM or ChaCha20-Poly1305. scrypt key derivation. An authenticated header that rejects tampering. Keyfile second factors. A one-time recovery key. Paranoid mode. Audited cryptography, with no third-party libraries standing between your files and the cipher.

Why ShadowBit?

Encryption that travels with you.

ShadowBit turns any collection of files into a single encrypted container you can email, carry on a USB drive, or share anywhere. No cloud, no account, no subscription. The vault is just a file.

Unlike zip encryption (weak and crackable), cloud-only vaults (require trust in a provider), or full-disk tools (not portable), ShadowBit gives you one file that travels anywhere and opens on any computer that has ShadowBit installed.

Recipes

Common workflows.

Share a vault
# Create — you will be prompted for a password
shadow-bit create shared --no-recovery
shadow-bit open shared
cp report.pdf <working-folder>/
shadow-bit close shared

# Send shared.svlt via email/USB
# Recipient opens with the same password
Recover a forgotten password
# Use the recovery key printed at creation
shadow-bit recover project
# Recovery key: A7KX9-MP2VQ-8NW4T-…
# New password: ********
# ✓ Password reset via recovery key.
Automate with scripts
# Set the password once, out of band.
# Prefer the env var over --password: the flag is
# visible to other users via `ps` and lands in
# your shell history.
export SHADOWBIT_PASSWORD="$VAULT_PASS"

shadow-bit create backup --no-recovery
shadow-bit open backup
rsync -av ~/Documents/ <working-folder>/
shadow-bit close backup
Migrate an existing folder
# One command seeds from a folder
shadow-bit create secrets \
  --seed ~/Documents/secrets

# Verify contents
shadow-bit open secrets
ls <working-folder>
shadow-bit discard secrets

Independently reviewed — and not professionally audited
ShadowBit has been through an internal code review whose findings are fixed and covered by an automated suite of 232 tests (crypto round-trips, the full keyfile lifecycle, the real CLI as a subprocess, the real desktop app, WCAG 2.2 AA, responsive reflow, and performance budgets). That is a self-review, not an independent security audit — read SECURITY.md and SECURITY_AUDIT.md in the repository for the full report and the threat model.

What is a Vault?

One file holds everything.

A .svlt file is a self-contained encrypted archive. It carries everything needed to decrypt it — KDF parameters, salt, wrapped master key, auth tag — except your password. Email it, put it on USB, attach it to a message. The recipient opens it with ShadowBit and the password you share out-of-band.

Envelope Encryption
A random 256-bit MEK encrypts your files. The MEK is wrapped by your password-derived key. Changing the password only re-wraps the MEK — instant.
Authenticated Encryption
AES-256-GCM or ChaCha20-Poly1305 with a fresh random IV. Wrong passwords and tampering are detected as decryption failures.
Authenticated Header
The entire header is protected by an HMAC-SHA256 (HKDF-derived from the MEK). Header tampering — inducing fake KDF params or recovery keys — is detected and rejected on open.
Recovery Key
An optional second independent wrapping of the MEK. A forgotten password isn't permanent lockout.
